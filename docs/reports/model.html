3.1 문서 개요

Cropy에 들어가는 두 모델을 다룬다.

  • CNN 병해 분류 모델: 사진을 보고 9개 클래스 중 하나로 분류한다. 지금 서비스에서 실제로 쓰고 있다.
  • Qwen3.5-2B 기능 선택 모델: 사용자 질문을 보고 어떤 기능을 부를지 고른다. Colab에서 학습 실험 중이고 아직 서비스에 연결하지 않았다.

어떤 모델을 왜 골랐는지, 어떤 데이터로 어떻게 학습했는지, 단말에 올리려면 얼마나 줄여야 하는지를 기록한다. 실험 결과는 develop에 병합된 ML PR(#22#24, #55, #59#61)과 그 PR에 들어간 보고서를 근거로 했다. 10월 13일 이후의 일부 실험(CNN 방향 민감성 조사, Qwen v17·v18·diagnostic32)은 아직 로컬 기록만 있고 GitHub에 올리지 않았기 때문에 표에 따로 표시했다.

3.2 모델 선정 및 개요

CNN: ResNet50 (ImageNet 사전학습 + 미세조정)

항목 값
구조 ResNet50, 마지막 FC를 9클래스로 교체
입력 224×224 RGB, ImageNet 평균·표준편차 정규화
출력 9클래스 softmax 전체 분포
파일 best_model.pth, 94,420,689바이트
보조 모델 무 혼동쌍 전용 ResNet18 2클래스(pair_mu.pth), 기본 꺼짐

학습 스크립트(ml/train.py)는 --arch resnet18|resnet50을 모두 지원하고, 백엔드도 체크포인트에 적힌 구조를 보고 알아서 불러온다. 본 모델은 ResNet50을, 무 혼동쌍 보조 모델은 더 가벼운 ResNet18을 쓴다.

ResNet50을 고른 이유는 세 가지다. ImageNet 사전학습 가중치로 적은 데이터에서도 미세조정이 잘 되고, 연산이 Conv·BN·ReLU 위주라 RKNN Toolkit으로 NPU 변환할 때 막힐 가능성이 낮다. 그리고 약 94MB라서 16GB 단말에 올리기에는 부담이 크지 않다. 경량 구조(MobileNet 계열 등)와의 비교는 아직 하지 않았다. 단말 CPU에서 1초 목표를 못 맞추면 그때 양자화와 함께 비교한다.

클래스 정의. 폴더 이름 앞 숫자를 그대로 model_class_id로 쓰고, 이 값으로 DB의 diseases 표와 연결한다. ImageFolder의 정렬 순서에 기대지 않기 때문에 나중에 클래스를 추가해도 기존 번호가 밀리지 않는다.

처음 계획은 Qwen이 진단 결과를 보고 설명 문장을 직접 쓰게 하는 것이었다. 그런데 2B 모델이 농약 이름이나 희석배수를 그럴듯하게 지어내면 실제 피해로 이어질 수 있다. 그래서 10월 초 데이터 초안부터 방향을 바꿔, 모델은 "무슨 기능을 부를지"만 고르고 실제 문장은 DB 값을 넣은 handler가 만들게 했다. 특강 1에서 소개된 전용 함수 호출 토큰 방식을 적용한 것이다.

2B를 고른 이유는 RK3588 NPU에서 돌릴 수 있는 크기이면서 한국어가 어느 정도 되기 때문이다. 강의 자료의 한국어 비교에서도 첫 후보로 나왔다. 더 큰 모델은 2B가 반복적으로 실패하고 메모리가 남을 때만 검토한다.

함수는 대부분 맞히는데 인자가 자주 틀린다. 예를 들어 "점수가 몇 퍼센트예요?"(confidence)와 "그 점수로 확정할 수 있어요?"(limits)를 헷갈린다. pilot50에서는 모든 입력에 같은 답 하나만 내는 문제가 있었는데, 원인을 찾아보니 FP16 loss scale 65536에서 처음 11스텝의 gradient가 NaN으로 터져 업데이트가 건너뛰어지고 있었다. scale을 32로 낮춘 비교 검사에서 3배치 모두 gradient가 정상으로 나왔고, 이후 diagnostic32에서는 100회 업데이트 중 건너뜀이 0회였다.

검증셋이 24~28행으로 작고 여러 실험에서 반복해 봤기 때문에 위 수치를 서비스 성능으로 쓰지 않는다. 사람 검수도 끝나지 않았다.

3.5 모델 경량화 및 최적화 방안

현재 상태

아직 경량화는 하지 않았다. 브라우저 기기 진단용으로 FP32 ONNX 변환만 해 두었다(#55). 같은 입력 텐서 3개로 PyTorch와 비교했을 때 logit 최대 차이가 1.4×10⁻⁶이었다.

산출물 크기 정밀도
PyTorch best_model.pth 94.4MB FP32
ONNX cnn-44441d36….onnx 94.0MB FP32
RKNN .rknn - 계획 (INT8)
Qwen LoRA 어댑터 수 MB 수준 학습 결과
Qwen .rkllm - 계획 (W8A8)

CNN 경량화 계획

진행 순서는 "먼저 재 보고, 모자라면 줄인다"다.

  1. 보드에서 지금 PyTorch 모델을 CPU로 돌려 기준선을 잡는다.
  2. 단건 1초 목표를 넘기면 스레드 수 조정 → ONNX Runtime CPU → RKNN INT8 순으로 비교한다.
  3. RKNN INT8 변환 시 캘리브레이션 이미지는 학습셋에서 클래스당 3060장, 총 300500장을 뽑는다. 검증·테스트 사진은 캘리브레이션에 쓰지 않는다.
  4. 채택 기준은 전체 정확도 하락 1.5%p 이내, 클래스별 하락 3%p 이내다. 무 노균병 재현율이 떨어지면 전체 기준을 통과해도 다시 검토한다.

가지치기(pruning)와 지식 증류는 이번 학기 계획에 넣지 않았다. INT8만으로도 크기는 약 1/4로 줄어들 것으로 보고 있고, 증류는 학습을 처음부터 다시 해야 해서 남은 일정에 무리라고 판단했다. INT8에서 정확도가 많이 떨어지면 혼합 정밀도나 QAT를 검토한다.

Qwen 경량화 계획

학습할 때 이미 NF4 4bit로 올려서 LoRA를 붙이고 있다. 배포는 다음 순서다.

Qwen3.5-2B + LoRA 어댑터 → 병합(FP16) → RKLLM Toolkit W8A8 변환 → .rkllm → 보드 RKLLM runtime

변환 후에는 원본·학습본·양자화본을 같은 질문 세트로 돌려 기능 선택 정확도, 첫 토큰 지연, 초당 생성 토큰, RAM을 비교한다. 출력이 토큰 34개라 생성 속도보다 첫 토큰 지연(프롬프트 처리)이 체감 속도를 좌우할 것으로 본다. 현재 입력 길이가 531725토큰이라, 시스템 프롬프트를 줄이는 것도 최적화 항목에 넣었다.
