주요 발견 사항은 세 가지다.

  1. 서버 쪽 오류 처리는 촘촘하게 테스트돼 있다. 저장 실패, 중복 요청, 동시 수정, 디스크 오류 주입까지 자동 테스트에 들어 있다.
  2. 모델은 전체 정확도는 높지만 무 두 병을 구분하는 능력이 기준에 못 미친다. 재촬영 기능이 이걸 얼마나 보완하는지는 아직 평가 자료가 없다.
  3. 병합 과정에서 기능이 빠지는 일이 두 번 있었다(D-05, D-06). 테스트가 잡아내지 못한 경우라 리뷰 체크리스트에 추가했다.

장시간 구동은 미실시. 대신 오류 상황에서 데이터가 깨지지 않는지는 자동 테스트로 확인하고 있다. 예를 들어 test_recovery_contracts.py의 test_concurrent_refinement_retry_returns_winner_without_deleting_its_photo는 재촬영 재시도가 동시에 들어왔을 때 먼저 저장된 결과의 사진이 지워지지 않는지 본다. test_diagnosis_integrity.py는 DB 커밋 실패 시 롤백과 새 사진 삭제, 모델이 바뀐 뒤 재촬영하면 409와 기존 상태 유지, 재촬영 사진 교체는 커밋 후에만 이전 파일 삭제 같은 경우를 다룬다. 마이그레이션 전 SQLite 백업과 외래키 위반 시 기동 중단은 test_database_migration.py에 있다.

5.2.5 결론 및 개선 권고

웹앱의 서버·화면 기능은 자동 테스트와 CI로 안정적으로 관리되고 있다. 테스트 수가 백엔드 367개, 프론트 665개로 늘었고, 오류 상황 테스트 비중이 높다. 반면 실제 기기에서 확인한 것은 PC Chrome뿐이고, 이 프로젝트의 핵심인 온디바이스 부분(보드 속도, 전력, 오프라인 음성)은 아직 손대지 못했다.

앞으로 할 일은 이렇게 정했다.

  1. 로컬 수정 3건(D-07~D-09)을 바로 PR로 올린다. 특히 위치정보 문제는 사용자 사진을 다루는 서비스에서 우선순위가 높다.
  2. 보드를 받으면 첫 주에 CNN CPU 기준선부터 잰다. 이 값을 봐야 RKNN 변환이 필요한지 정할 수 있다.
  3. 무 병해 평가 자료를 따로 모은다. 지금은 재촬영 기능이 정확도를 실제로 올리는지 보여 줄 근거가 없다. 잎 앞면과 뒷면을 같은 잎에서 찍은 쌍을 모아야 한다.
  4. 병합 충돌 후 체크를 강화한다. D-05, D-06 모두 충돌 해결 중에 생겼다. 충돌이 있었던 PR은 병합 전에 관련 기능을 한 번 직접 돌려 보도록 리뷰 규칙에 넣는다.
  5. 실제 휴대폰 테스트를 9주차에 끝낸다. 아이폰 HEIC와 갤럭시 RAW는 생성한 테스트 파일로만 확인했다.
